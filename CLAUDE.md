# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Purpose

> Provenance note: llm-redact was developed privately before its public
> v1.0.0 debut; the public version numbering starts there. This document
> and the docs/ tree deliberately avoid the private lineage's internal
> version numbers.

llm-redact is an LLM information redactor: it prevents private information from being sent to LLMs by agentic tools. It substitutes placeholders for private information on outgoing requests, then restores the real values in incoming responses, transparently to the agentic tool's user.

## Open-core placement rule (owner's standing instruction)

Paid features (Pro tier and above) live in the separately-distributed
**llm-redact-pro** package, and stay there to the greatest extent possible.
This repository keeps only the redaction/rehydration product, generic seams
(`plugin_api` + `registry`), and the security floors that must hold even
without llm-redact-pro, such as never forwarding a proxy credential. When
adding or changing a Pro feature, put the implementation in llm-redact-pro.
**Before writing any Pro-feature code in this repository — a new seam, a
config shape, a user-facing surface, or a guard — ask the owner first**,
explaining why it belongs here. Never add authentication, user or seat
logic here.

## Architecture

One request flows: agentic tool → proxy (`proxy.py`) → provider adapter redacts → upstream LLM API → adapter rehydrates → tool.

- **Outbound (redaction)**: `detection/` (regex rules + validators; optional NER behind the same `Detector` protocol via `[detection.ner]` — backends spacy (`ner` extra), gliner, and presidio (`presidio_ner.py`: `PRESIDIO_TYPE_MAP` folds EMAIL_ADDRESS/PHONE_NUMBER/US_SSN/IBAN_CODE/CREDIT_CARD into the built-in placeholder types so one value never gets two token identities; `score_threshold` valid for gliner+presidio, rejected for spacy)) finds values; `redactor.py` resolves overlapping detections (longest/highest-priority wins; NER runs at priority 120 so structured rules win ties) and substitutes vault-issued placeholders. Per-rule modes (`[detection.modes]`): configured by RULE NAME, dispatched by DETECTOR TYPE via `build_modes` (rules sharing a type must agree; unknown names are build-time errors, deferred past `parse_config` like `enabled`). Dispatch happens AFTER overlap resolution — the winner's mode governs. USER DENY STRINGS (`[detection] deny` sugar / `[[detection.deny_strings]]`, `detection/deny.py`): literal substrings, case-insensitive unless flagged, tier 0 — a two-phase `_resolve_overlaps` makes them win EVERY overlap (a rule match merely starting earlier cannot claim the span), they bypass the allowlist, and they ALWAYS redact (modes never apply, even on type collision — structural in `redact_text`, not config). With no deny entries the old sweep runs unchanged (property-tested). Deny values must not contain guillemets; error messages name positions, never values. PER-TYPE ALLOWLISTS (`[detection.allowlist_by_type]` TYPE = [values], `Allowlist.allows_for`): exact values allowed for ONE detector type only; deny (tier 0) bypasses these too (pinned by test). LANGUAGE SCOPING (`[detection] languages`, unset = ALL = historical behavior): national-id rules carry ISO 639-1 tags (`RegexRule.languages`; None = universal — emails/IPs/vendor/credit_card/iban/phone always run); a tagged rule with no overlap is NOT BUILT (`active_rule_names` is the single list build_detectors instantiates AND the editor/status report — `language_inactive_rules`), the NER type-suppression set is computed from the ACTIVE list (a type whose only rule is scoped out stays out), and an enabled NER whose `language` is outside the list is a parse-time ConfigError; codes are lowercased+sorted at parse. Validated national-id rules (ALL grouped-display-form + checksum; bare digit runs never fire): `canadian_sin` (grouped 9 digits, Luhn; only area 8 rejected — area 0 stays allowed because 046 454 286 is the government's own example), `uk_nino` (HMRC grammar + invalid-prefix blacklist {BG,GB,NK,KN,TN,NT,ZZ}; the QQ reserved prefix is excluded by the grammar itself), `aadhaar` (4-4-4, Verhoeff, lead 2-9; the corpus derives Verhoeff from the D5 group law so table typos fail the recall gate), `australian_tfn` (3-3-3, ATO mod-11 — SAME grammar as canadian_sin: SIN wins exact-span ties by registration order, and TFN corpus values lead with 8 so _sin_ok rejects them), `spanish_dni` (DNI/NIE mod-23 control letter; solid form safe because the letter validates; declares no prefilter literals like credit_card), `french_nir` (spaced display form incl. Corsican 2A/2B, mod-97 key; priority 90 because the loose 13-19-digit card grammar covers a spaced NIR and 1/10 of NIRs are Luhn-valid — the tie must go to the NIR-specific grouping), `german_steuer_id` (spaced 2-3-3-3, repeat-structure + ISO 7064 MOD 11,10), `brazilian_cpf` (dotted 000.000.000-00, dual mod-11, all-same-digit rejected), `italian_codice_fiscale` (16-char grammar + day range incl. +40 female form + mod-26 check letter; the corpus transcribes the odd-position table INDEPENDENTLY and RSSMRA85T10A562S pins both; omocodia out of scope), `belgian_nn` (Rijksregisternummer dotted YY.MM.DD-NNN.CC, two check digits = 97 - body mod 97 with the post-2000 '2' century prefix accepted, month/day 0 allowed; 93.05.18-223.61 pins it), `finnish_hetu` (henkilötunnus DDMMYY + century sign + NNN + mod-31 check char; the sign letter makes the solid form safe like codice_fiscale — the corpus builds the check alphabet by FILTERING out G/I/O/Q so a typo fails recall, 131052-308T pins it), `nhs_number` (UK 3-3-4 SPACED display form only, mod-11 with 10-invalid; the space form is disjoint from the phone grammar — the hyphenated form is a phone shape, not NHS; 943 476 5919 pins it), `norwegian_fnr` (fødselsnummer DDMMYY-NNNNN spaced/hyphenated, DOUBLE mod-11 with either check landing on 10 = invalid; weights transcribed independently in the corpus), `korean_rrn` (resident registration number YYMMDD-SBBBBNC hyphenated 6-7 form ONLY, weighted mod-11 + month/day/gender-digit gates; priority 90 like french_nir because the 13-digit hyphenated span is also a valid credit_card grammar and ~1/10 pass Luhn — the RRN grouping must win the exact-span tie), `singapore_nric` (NRIC/FIN [STFG]+7digits+check letter, S/T and F/G share weight-2765432 tables with T/G adding 4; the bracketing letters make the solid form safe, S1234567D pins it). Dutch BSN deliberately absent (customarily bare 9 digits; the 11-test passes 1/11 of random runs). CRYPTO WALLET ADDRESSES (`detection/wallet_checksums.py`, all checksum-vetoed, priority 20): `eth_address` (ETH_ADDRESS, `0x`+40hex — EIP-55 mixed-case keccak-256 checksum; all-lower/all-upper accepted on shape, single-nibble null/burn rejected; keccac-256 is VENDORED because hashlib only ships NIST SHA3 which uses a different pad byte — pinned to the empty/`abc` Keccak vectors), `btc_address` (BTC_ADDRESS, base58check P2PKH `1…`/P2SH `3…`, double-SHA256, version 0x00/0x05, declares no anchor like iban), `btc_bech32` (BTC_ADDRESS shared, `bc1…` segwit — BIP-173 bech32 for witver 0, BIP-350 bech32m for v1+ taproot). The corpus reuses the ENCODE side of the same primitives, so correctness rests on the independent published spec vectors in test_wallet_checksums.py (a self-consistent keccak bug would otherwise pass recall). Vendor tokens are prefix-anchored ONLY — Cloudflare/Vercel have no prefix and are deliberately excluded; `sb_publishable_` and similar non-secret forms are deliberately unmatched; the GitLab routable-token family beyond `glpat-` (`gitlab_token`: glrt/glcbt/gldt/glptt/glagent/glimt/glsoat), `google_oauth_client_secret` (GOCSPX-), `sentry_token` (sntrys_/sntryu_), `xai_key` (xai-), `perplexity_key` (pplx-), `hashicorp_vault_token` (hvs./hvb.), `langsmith_key` (lsv2_pt_/lsv2_sk_), `replicate_token` (r8_), `pinecone_key` (pcsk_), `new_relic_key` (NRAK-), `grafana_service_account` (glsa_…_hex), `jina_key` (jina_), and `telegram_bot_token` (8-10 digit id : 35-char secret, no single anchor) are covered; `aws_access_key_id` matches ASIA (STS temporary) as well as AKIA; the legacy unprefixed GitLab CI_JOB_TOKEN and 64-hex Sentry token stay out (no anchor). NER is MULTI-BACKEND: `[detection.ner] backends = [..]` runs any combination of spacy/gliner/presidio/stanza/hf concurrently (stanza = `stanza_ner.py`, Stanford Stanza `Pipeline(lang, processors="tokenize,ner")`, multilingual, NO confidences like spacy; hf = `hf_ner.py`, transformers `pipeline("token-classification", aggregation_strategy="simple")`, any Hub model, emits confidences so score_threshold applies — `_confidence_backends = gliner/presidio/hf`; both build-dispatched in `build_detectors` and validated in `known_backends`) (legacy single `backend` = one-element form; `[detection.ner.models]` per-backend model overrides — the legacy `model` key applies only when exactly one backend is active; score_threshold rejected only when NO confidence backend is active). PER-TYPE SINGLE SOURCE OF TRUTH: a placeholder type disabled at the rule level is suppressed for NER emissions too (TypeFilteredDetector wraps every NER backend; PERSON has no builtin rule so never suppressed); the dashboard NER card has per-backend checkboxes/models and a live folded-type state line. NER language/model (`[detection.ner] language`, `model`): spaCy pipeline name for spacy/presidio (default en_core_web_sm), HF id for gliner (default urchade/gliner_small-v2.1); presidio wires language through NlpEngineProvider and `analyze(language=...)`; presidio's EmailRecognizer validates TLDs against the public-suffix list, so `.example` addresses score zero (real-analyzer smoke test uses `.com`). HOT-PATH PREFILTER (`regex_rules.py`): rules declare `required` literal CNF (necessary conditions; skipped entirely when unsatisfied — one shared `PreparedText` caches the lowered haystack) and `anchors` (every match starts with the literal → find-then-match via `pattern.match(text, pos)`, which keeps \b/lookbehinds correct; CI anchors fall back to plain finditer when lowering changes string length, e.g. 'İ'). Equivalence is machine-checked: per-rule soundness tests over the recall corpus plus a differential fast-vs-naive suite — a wrong literal declaration is a silent recall bug, so never add one without its generator coverage. credit_card/iban deliberately declare nothing. PER-STRING GATE (`engine.DetectorPlan`/`plan_for`, a WEAK cache — a plan lives exactly as long as a Redactor holds it, so a reload's old detectors (NER models included) die with the last request using them; every Redactor copy shares its plan): for a text of at most `GATED_MAX_CHARS` (1024) only candidates run — a literal rule when a literal of one of its CNF groups occurs in its own haystack (indexed by first character: exactly its prefilter's test), the literal-less rules with no capturing group and no flag through ONE combined alternation (it matches nowhere exactly when none of them does), everything else (deny strings, NER, plugin and other custom detectors) always — in list order through the unchanged per-detector code, so detections are identical; longer texts run every detector. tests/test_detector_plan.py proves it against the full scan over the recall corpus, its non-ASCII-digit rewrites and the fp corpus at every length, and dropping any gate literal or combined member must fail it. Haystacks are Unicode-exact: case-sensitive literals test `PreparedText.folded` (decimal digits of every script folded to ASCII, same offsets — `\d` matches them all), case-insensitive ones `PreparedText.lower` (`lower_for_ci` maps İ/ı/ſ first, keeping CI anchor offsets 1:1); user literals are folded alike, and validators indexing ASCII tables (codice fiscale, CURP) fold digits first. CUSTOM-RULE VALIDATORS (`detection/validators.py`, `[[detection.custom_rules]] validator=`): a named checksum/format gate resolved in `build_detectors` and hung on the RegexRule's `validator` — `luhn`/`mod97` (accepts plain MOD-97-10 AND the IBAN move-first-4 layout)/`verhoeff`/`jwt` (base64url header+payload decode to JSON objects)/`entropy` (≥3.5 bits/char, ≥16 chars, no whitespace — the loose-pattern-plus-check recipe made user-facing); an unknown name is a build-time ValueError (deferred past parse_config like modes). Custom rules also accept `required` (each literal → a single-alternative CNF clause) and `anchors` passed straight through to RegexRule — a wrong hint is the user's silent-recall risk, opt-in and off by default; all three round-trip through the emitter and the editor view. `warn` counts the type and deliberately forwards the value upstream (no vault write); `block` raises `BlockedRequest` (type only, never the value) which `handle()` turns into a provider-shaped **400** (not 403 — SDK UX) before any upstream contact, on CHAT and REDACT_ONLY routes alike. `jsonwalk.py` applies redaction to every string value in the request body (skipping only SCALAR values of `STRUCTURAL_KEYS` like `model`/`role`/base64 `data` — objects/arrays under a structural key are WALKED (a tool result nested under `data`/`name`/`id` once skipped its whole subtree: a leak); `OPAQUE_POSITIONS`/`OPAQUE_ANYWHERE` (tool-call args, tool results, `documents`, keyed by (parent key, key), list items inheriting their list's key — and the maps whose keys the CALLER chooses: `metadata`/`requestMetadata` anywhere, (`prompt`,`variables`), a body's top-level (None,`instances`)/(None,`parameters`); a value under a caller key named `id`/`name`/`type`/`data` once went upstream unredacted) are walked with NO skips at all; `ENUM_LIST_POSITIONS` skips the modalities enum arrays; `MEDIA_POSITIONS` (`source.bytes`, Bedrock base64 media) skip STRING values like base64 `data`; plaintext documents with `source.type == "text"` have their `data` scanned; image responses' `b64_json` stays skipped) so system prompts, nested content blocks, and tool results are covered without hardcoded body shapes. REPEATED KEYS: request JSON is parsed with `jsonwalk.loads_request` (an `object_pairs_hook` flags a repeated key at any depth; a second plain parse runs only for a flagged document). The parse keeps the LAST occurrence, so a flagged body never takes `handle()`'s no-op short-circuit (the raw bytes still hold the earlier occurrences, which a first-wins upstream reads) and is re-serialized from the walked object — `detection = false` included, where exactly what the ownership check read is sent; uploaded JSONL lines likewise (`openai._parse_request_line`), a Bedrock count-tokens blob with a repeat is `UnredactableRequest` (400: the envelope short-circuit cannot see inside it), and realtime client frames are always re-serialized (`_dump_frame`). SERIALIZATION: re-serialize JSON only through `jsonwalk.json_text`/`json_bytes` (exactly `json.dumps(ensure_ascii=False)` output, a lone surrogate re-escaped instead of failing the UTF-8 encode) — every request, answer, listing, stream-adapter, realtime-frame, JSON-log and doctor `--json` site does; never `json.dumps(..., ensure_ascii=False).encode()`. Unchanged bodies still forward byte-identical. BOUNDED DEPTH: every client/upstream JSON parse goes through `jsonwalk.loads_bounded`/`loads_request` (`JsonTooDeep` past `MAX_JSON_DEPTH` 128, or a RecursionError): the client side is refused (scanned-body 400, upload line/field 400, Bedrock blob 400, realtime 1008), the upstream side forwarded verbatim, never a 500; keep the limit well below 1000/4 (mutmut's trampolines overflowed at 256). Oversized redactable bodies are rejected 413 fail-closed (`max_body_bytes`), and so are bodies with more strings to redact than `max_body_strings` (default 100,000, hot, snapshotted per request with `max_body_bytes`; redaction runs string by string on the event loop, which bytes alone did not bound): `Redactor.with_budget` charges every `redact_text` (JSON strings, form fields, file names; floor copies share the count) and the OpenAI multipart hook charges each uploaded file's lines (a byte count) before any split; `TooManyStrings` (an `UnredactableRequest`, so an unaware path still refuses) becomes the same recorded 413 via `_body_too_large`; a multipart body's parts are bounded by its delimiter count before any parse (`_multipart_parts_over`); realtime gives each client frame its own budget (close 1009, row 413). `detection = false` providers and pass-through redact nothing and are not counted.
- **Vault** (`vault.py`): deterministic — same `(session, type, value)` always yields the same `«TYPE_NNN»` token (format in `placeholders.py`); the mapping never leaves the machine. `InMemoryVault` (default) dies with the process; `SqliteVault` (`[vault] backend = "sqlite"`, `--session`) persists across restarts with 0600/0700 permissions, WAL + `synchronous=FULL` (counter reuse after a lost write would silently rehydrate the wrong secret) + `busy_timeout` (concurrent WAL writers wait, not error), and a write-through cache keeping reverse lookups off the DB on the streaming hot path. WRITE-FAULT FAIL-CLOSED: `placeholder_for` rolls back and re-raises on ANY exception (a sqlite write error, a cipher fault — not just IntegrityError) so a disk-full/IO fault under `isolation_level=None` can't leave the open `BEGIN IMMEDIATE` wedging the next request (EncryptedInMemoryVault encrypts before changing state); caches write only after COMMIT (nothing poisoned) and n is read fresh inside the write transaction, so a retry reissues the SAME number (test_vault_faults.py). TOKEN FLOORS: every session numbers from 001, so a request can carry tokens its session never issued (a compacted history forked into a fresh session, a pasted answer, another proxy's token). `Vault.placeholder_for(type, value, *, floor=0)` numbers a NEW value `next_number` = max(MAX(n), retired, floor)+1 (a mapped value keeps its token; the gaps a floor asks for are the only gaps, never a reuse); past `MAX_TOKEN_NUMBER` (999999999) `PlaceholderSpaceExhausted` → the Redactor's `PlaceholderLimitReached` (an `UnredactableRequest`: 400 / realtime close, nothing written). Floors come from `placeholders.token_floors`/`json_floors` (every key and string of the decoded body; a superset of `PLACEHOLDER_RE` and the fuzzy grammar plus escaped guillemets) behind the byte gate `may_carry_tokens` (0xAB, `\u00`, NUL for UTF-16/32, `%AB`); the Redactor holds them immutably (`with_floors` returns itself or a thin copy, so the shared static redactor is never floored; `floor=` only for a type the request carries). Sources: `handle()` JSON bodies, `OpenAIAdapter.redact_multipart` (`_multipart_floors`: the whole upload before any part), the decoded Bedrock count-tokens blob, realtime `frame_floors` (a running floor over CLIENT frames only — a `session.updated` echo carries the note). The system note's example token is «EMAIL_000», a number never issued. PER-REQUEST BATCH (sqlite): `vault.run_batched(vault, work)` wraps `prepare_request` (Bedrock count-tokens included), `redact_multipart` and each realtime `redact_message` — `BEGIN IMMEDIATE` lazily at the first new value, staged rows visible to the request's own lookups, ONE COMMIT (one fsync) before anything is forwarded, caches only after it; any exception (a write or COMMIT fault, a block, a string cap, a cipher fault, a vault error the work swallowed — `_Batch.failure`) rolls the whole batch back with caches untouched, so a retry reissues the same numbers. The callable form is deliberate — `work` cannot await; never turn it into a context manager. Views on one connection share the batch (`_Connection`, re-entrant); `_revalidate` never runs inside one; other processes wait on `busy_timeout` and fail closed. RDBMS and memory vaults run per call (the RDBMS reconnect and UNIQUE retries replay ONE self-contained allocation). A vault fault there is a recorded, provider-shaped 503 before any upstream contact (`_vault_fault_refused`, bookkeeping stage `vault`, logged by exception type; realtime closes 1011, row 503): `proxy.vault_fault_types` = `sqlite3.Error` plus the manager's optional `fault_types` (RDBMS: the driver's Error and `RdbmsAllocationError`), resolved once. RETIRED NUMBERS: every whole-session delete (the TTL prune, `POST /__llm-redact/sessions/prune`, the CLI prune, `SessionStore.forget`) raises the session's retired number (sqlite `retired_numbers`, RDBMS `llm_redact_retired`; never lowered, never deleted) in its own transaction, and allocation reads max(MAX(n), retired) in one statement — no (session, type, n) ever carries two values, so another instance's stale cache or a live realtime view restores a token to its own value or passes it through. The retired number is also the epoch: views load it first, re-check every `CACHE_CHECK_SECONDS` (1 s, injectable `clock=`) and rebuild on change; a `_revalidate` that cannot read the database keeps the caches and retries next interval (safe: retired numbers mean a cached token restores only its own value; `vault.CheckFaults` logs once per outage by type and counts bookkeeping stage `vault_check` through the optional `bind_fault_counter`), `_load` assigns all-or-nothing, and a fault while `context_for` opens a session is the vault-fault 503 (WS 1011). `VaultManager`s hand out per-session views over one shared connection, ONE live view per session (a weak `_live` registry behind the ~64-entry LRU; a local prune/forget rebuilds every live view of the deleted sessions); the in-memory manager forgets in place (`forget_mappings`, numbering kept) and, like the persistent ones, counts and lists only sessions holding mappings. The prune's idle check and its delete are one transaction (sqlite: inside the write lock; RDBMS: a per-session re-check, `DELETE … n <= M`). Managers persist the Responses `response_id → session` map (`response_sessions`; the ~10k cap trims ONLY rows whose session holds no mappings — a router reads a missing row as "pruned", and resuming a LIVE session's chain in a fresh one would reissue «EMAIL_001» for a new value; live sessions' rows leave with the session via prune); stored-object owner records mirror there through the optional `record_object_session` (kind `object`, bounded apart from Responses rows by `_MAX_OBJECT_ROWS`, 10,000), and `lookup_response_sessions` answers many ids in one query per `LOOKUP_CHUNK` (500). `[vault] encryption = "fernet"` (`crypto` extra, `LLM_REDACT_VAULT_KEY`) stores a domain-separated HMAC index + Fernet ciphertext (schema v3); the MEMORY backend honors fernet too (EncryptedInMemoryVault: HMAC index + ciphertext in RAM, decrypt per reverse lookup, deliberately NO plaintext cache; key resolution and fail-closed behavior shared); migration is one-transaction encrypt-in-place followed by `wal_checkpoint(TRUNCATE)` + `VACUUM` (else plaintext lingers and the at-rest claim is false); wrong/missing key fails closed AT OPEN; caches stay plaintext-keyed so the hot path is unchanged. KEY RESOLUTION (`vault_crypto.from_env`): env var (`LLM_REDACT_VAULT_KEY`) → key command (`LLM_REDACT_VAULT_KEY_CMD`, `key_from_command`: run via shell, stdout stripped, for service units with no `$(...)` shell — a failing command logs by exception TYPE only since CalledProcessError carries captured output that could hold the key, timeout `_CMD_TIMEOUT_S`) → OS keychain (`keyring` extra, `llm-redact vault set-key`, service "llm-redact"/item "vault-key") → fail closed; every non-env source that errors counts as key-absent (never a silent downgrade, never a traceback), and error messages name the key SOURCE without echoing key material. - **Proxy** (`proxy.py`): catch-all route. Unrecognized traffic forwards verbatim — but only to the provider it is positively attributed to (PROVIDER ATTRIBUTION, Providers bullet; unattributable → a recorded 404) and only with the client's own credential (a credential the proxy holds is lent to recognized routes only); a recognized route forwards only a body it scanned (SCANNED-BODY RULE below). ORDER in `handle()`: target, dot- and empty-segment 400s → reserved paths → admission (the gate scrubs its credentials) → route + `_misaddressed` → `provider_for` → `upstream_auth` snapshot (read ONCE with `provider_conf`, before the body await: a reload landing mid-body never changes what a request was admitted as, and the upstream comes from the same snapshot — `ProxyState.upstream_for` is gone) → REQUEST ORIGIN → `GET`/`HEAD /` answered locally → misaddressed / unattributed / unknown-custom / disabled-provider / gate refusals → the identity unrecognized-route 403 → `local_answer` → an unrecognized route's plan (lending → 403) → the capped body read and `loads_request` → a recognized route's `plan()` (lending → the request-origin host rule again, markers or not) → the SCANNED-BODY RULE (parts cap first) → `_ownership_body` + `object_access_refusal` → `context_for` → redaction in `run_batched` → routed or legacy delivery. REQUEST ORIGIN (`request_origin_refusal`, threat-model 'Requests from web pages'): the vault is lent on every rehydrating route (a page with its own key read it back through a relayed CORS answer, a WebSocket, or after DNS rebinding) and identity/operator keys on some, so every forwarded HTTP request is checked right after admission — before the `GET /` answer, the misaddressed/unattributed/disabled-provider/gate refusals, the body read and any credential — and every WS upgrade first of all: browser markers (Origin, any Sec-Fetch-*; page script can neither set nor remove them) require `_host_allowed` (loopback names, the bind host, `allowed_hosts`, the gate's public origin) plus either the request's own origin (port-exact `_own_origin`) with Sec-Fetch-Site same-origin/none, or every foreign Origin exactly in the operator's opt-in `allowed_origins` (`config.normalize_origin`: http(s) only, plain http only on loopback, never `null`; Sec-Fetch-Site then skipped; a request with no Origin is never listed); a request spending a proxy-held credential (the identity snapshot; a routed plan's `_lends_credential`, re-checked once planned) needs `_host_allowed` even without markers unless its scheme is https/wss (a browser checks the certificate against the name it resolved). Refusals: a recorded provider-shaped 403 (`_request_origin_refused`) / WS accept-then-close 1008; `/status` `request_origin_refusals_total{host,origin,fetch_site}`; kind-only logs. `allowed_hosts`/`allowed_origins` are restart-only (in RESTART_ONLY_KEYS, so the pro editor preserves them); reserved paths never consult `allowed_origins`; CORS for listed origins is transparent (preflight forwarded, the provider's answer relayed; proxy-generated errors carry no CORS headers); `/status` `allowed_origins` is the count; doctor `_check_allowed_hosts` (WARN: a plain-HTTP non-loopback bind lending a credential with none listed) and `_check_allowed_origins` (WARN listing them); a status posture line; the Helm standalone mode emits its Service names as `allowed_hosts`. ## Testing conventions

The load-bearing suites are the chunk-split sweeps: `test_rehydrate.py` and `test_sse.py` split inputs at every offset and assert streaming output equals non-streaming output; they are parametrized over `fuzzy` and json-source-escape modes. When touching `rehydrate.py`, `sse.py`, or an adapter's event handling, extend those sweeps rather than adding single-case tests; `test_eventstream.py` mirrors the convention for the binary codec (golden fixtures assembled longhand, never via the codec's own serializer), `test_ndjson.py` for the NDJSON line codec, and `test_properties.py` (hypothesis, deadline=None) probes the same invariants with random inputs — it extends, never replaces, the sweeps. Integration tests (`test_proxy_integration.py`) run the real app in-process against fake upstreams via `httpx.ASGITransport` — NOTE: ASGITransport joins response body parts into one chunk, so chunk-boundary behavior can't be pinned through it (test_provider_bedrock.py's `_ChunkedUpstream` custom transport exists for exactly that). The mTLS suite (`test_tls.py`) is the one real-socket exception: throwaway PKI via cryptography (importorskip), uvicorn on port 0 in a thread. NER unit tests inject fake models (spaCy nlp / GLiNER / a fake Presidio analyzer) so the suite runs without any extra installed. The RESILIENCE suites prove fault behavior: `test_upstream_faults.py` (connect/timeout/mid-body drops fail closed with a recorded 502; the streaming generators finalize on a mid-stream drop), `test_stream_truncation.py` (a stream ending mid-token flushes the partial verbatim — `feed(prefix)+flush()` == `rehydrate_text(prefix)` at every truncation), `test_vault_faults.py` (write-fault rollback, dense counter, corrupted-ciphertext fail-closed), and `test_soak_concurrency.py` (a `soak` marker, deselected by addopts, run as its own CI step — cross-session isolation + counter density + bounded LRU eviction under many connections); faults are injected with fake transports/conns, never real sockets or disks. Live-API tests (`-m live`) are deselected by default via addopts and double-gated on `LLM_REDACT_LIVE=1` + API keys; the `/v1/responses` drift detector asserts observed event types ⊆ `KNOWN_EVENT_TYPES`, and the Bedrock one (AWS_BEARER_TOKEN_BEDROCK) asserts ConverseStream `:event-type`s ⊆ `KNOWN_CONVERSE_EVENT_TYPES`. The ner CI job installs presidio alongside spaCy and runs test_presidio.py's real-AnalyzerEngine smoke test (skips wherever the extra or model is absent); OTel tests inject fake tracer/meter the same way. ISOLATION (`tests/isolation.py` + `conftest.pytest_configure`, before collection): `HOME` and `XDG_CONFIG/DATA/STATE_HOME` point into one throwaway directory for the whole session (subprocesses inherit it; `XDG_CACHE_HOME` stays real for third-party libraries), deployment `LLM_REDACT_*` variables plus `CLAUDE_CONFIG_DIR`/`CODEX_HOME` are dropped (`LLM_REDACT_TEST_*`, `PRO_*`, `LICENSE_*`, `LIVE*` and the live-model variables kept), and a session guard fails the run on any change under the real llm-redact dirs, agent command dirs or the user service unit (`LLM_REDACT_TEST_ALLOW_REAL_DIR_CHANGES=1` opts out); use the `isolation_root` fixture, never `import conftest` (mutmut re-imports it). Request-path suites of the hardening round prove each refusal end to end and that nothing reached the upstream or the authorizer: test_request_origin.py/test_allowed_origins.py (+ real-socket test_realtime_request_origin.py), test_scanned_body.py, test_request_attribution.py (a table of documented tool request shapes asserting upstream host, credential and redaction), test_upstream_redirects.py, test_lent_credentials.py, test_realtime_reload.py; the vault invariants ride test_vault_floors.py (every backend), test_token_floors*.py, test_vault_batch*.py, test_vault_deletion.py and the test_vault_properties.py state machine (a token restores to its own value or nothing), whose never-wrong-value rules the hypothesis machine in test_properties.py shares (floored writes: each number is max(previous, retired, floor) + 1).

Placeholders use guillemets (`«»`) precisely because they don't collide with code/markdown; don't change the token format without updating `viable_prefix_start` holdback logic, the fuzzy grammar (`FUZZY_PLACEHOLDER_RE`/`canonicalize`), and the split sweeps together.

## Known limitations (deliberate scope)

Bracket-swap/ASCII-guillemet mangles (`[EMAIL_001]`, `<<EMAIL_001>>`) are never restored — too collision-prone with real code. Base64 media is not decoded and scanned (images can't leak through text regexes; PDFs would need parser deps) — on realtime streams that includes voice audio: only the TEXT modality is redacted, and what a user says aloud goes to the provider as-is. Realtime WS connections use the static vault session (per-conversation anchors don't exist at upgrade time) — with llm-redact-pro's named users, each user's own copy of it (`context_for` goes through the session router, which scopes by user; the same holds for batch/conversations/context-caching flows). Synthetic flush events on the Responses stream omit `sequence_number`. Originals that arrive *pre-escaped inside request JSON-source strings* are captured in escaped form. Per-conversation mode: history compaction rewrites the first-message anchor and forks a fresh session — deliberately fails pass-through-verbatim (never wrong-value); forks are counted and surfaced (`compaction_forks`), and relink is a rejected design (docs/compaction-relink.md). Bare-digit phones/SSNs never fire (collision-prone); street addresses and passport/DL numbers are out of scope (no reliable grammar); `+`-prefixed integer literals (INT_MAX in code) match the solid E.164 phone form — pinned in the fp-corpus manifest. Warn mode is observation only: the matched value (and anything a longer warn-mode match overlaps) IS forwarded upstream — docs must never imply protection. The same honesty applies to the other deliberate opt-outs: `[providers.NAME] detection = false` (whole provider unredacted, rehydration active), `[detection.mcp] exempt_servers` (named MCP servers' blocks), and `[detection] languages` (scoped-out national-id rules are not built) — all surfaced in /status, never silent. A body the proxy cannot read is refused where redaction applies rather than forwarded unscanned — a non-JSONL file upload (`/v1/files`: a PDF, text, CSV or image) included; `detection = false` for that provider is the way to send one. Values a client deliberately encodes inside a string it sends (base64 in a JSON string) and structural names (JSON keys, multipart header names and the part `name`) are never scanned. Token floors are per request (per connection on realtime): a foreign token that arrives after its number was issued, or one another request of a shared session carries, is the documented residual. TTL "idle" means no new value in N days, so on a shared vault one instance can prune another's static session (its tokens then pass through verbatim, never wrong); retired-number rows grow by one per deleted session; an instance older than this release sharing a vault deletes without retiring numbers. Realtime connections under key auth relay non-JSON frames verbatim, and with `detection = false` under identity relay frames untouched. Vault encryption is at-rest only (memory holds plaintext) and the v2→v3 migration is one-way. RDBMS vaults fix the encryption mode at schema creation (no encrypt-in-place, no key rotation — server MVCC would keep scrubbing-proof old row versions; stand up a fresh schema instead), and `vault verify/rotate-key/backup` are sqlite-only. Multi-instance sharing of one vault database is safe but pays a round trip per first-sight allocation. The (llm-redact-pro) config editor rewrites the TOML file without preserving comments (one .bak kept). Supported platforms are Linux and macOS (both CI-tested); Windows is unsupported (SIGHUP reload alone would not save it). Non-loopback binding is fail-closed behind mutual TLS (`[tls]` certfile+keyfile+client_ca, enforced by `serve`); keep the proxy on 127.0.0.1 unless you operate a client-cert PKI — the written threat model lives in `docs/threat-model.md`.
